# Контекст API для бэкенд-разработчика

## 1. Назначение документа

Документ описывает данные и операции, которые уже требуются текущему
фронтенду приложения English Learning.

В проекте пока нет реальных HTTP-вызовов. Вместо них используются локальные
данные, `setTimeout`, `Promise.resolve()` и `console.log`. Приведённые ниже
URL — рекомендуемый REST-контракт, который нужно согласовать перед
реализацией.

## 2. Клиент и общие соглашения

- Клиент: Vue 3, Pinia, Vuetify, TypeScript.
- Приложение работает как web SPA и как Android-приложение через Capacitor.
- Предлагаемый префикс: `/api/v1`.
- Основной формат: `application/json; charset=utf-8`.
- Даты: ISO 8601 в UTC, например `2026-07-28T10:20:30.000Z`.
- Телефон передаётся в каноническом формате E.164: `+7XXXXXXXXXX`.
- ID слов сейчас имеют тип `number`.
- ID пользователя сейчас имеет тип `string`.
- Все закрытые endpoint’ы требуют авторизации.
- Клиенту потребуется переменная окружения `VITE_API_BASE_URL`.

Рекомендуемый формат ошибки:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте введённые данные",
    "fields": {
      "phone": ["Телефон указан неверно"]
    },
    "requestId": "optional-request-id"
  }
}
```

Ожидаемые статусы:

- `400` — некорректный запрос;
- `401` — отсутствующая или истёкшая сессия;
- `403` — операция запрещена;
- `404` — сущность не найдена;
- `409` — конфликт, например телефон уже зарегистрирован;
- `422` — ошибка валидации полей;
- `429` — превышен лимит попыток;
- `500` — внутренняя ошибка.

## 3. Инвентаризация необходимых вызовов

| Область | Операция фронтенда | Сейчас | Рекомендуемый endpoint |
| --- | --- | --- | --- |
| Авторизация | Вход по телефону и PIN | Локальная заглушка | `POST /auth/login` |
| Авторизация | Регистрация | Локальная заглушка | `POST /auth/register` |
| Авторизация | Выход | Локальная заглушка | `POST /auth/logout` |
| Авторизация | Восстановление сессии после перезагрузки | Отсутствует | `GET /users/me` |
| Профиль | Изменить имя | Локальная заглушка | `PATCH /users/me` |
| Профиль | Изменить аватар | Локальная заглушка | `PUT /users/me/avatar` |
| Профиль | Изменить PIN | Локальная заглушка | `PUT /users/me/pin` |
| Словарь | Получить список с поиском и сортировкой | Локальная заглушка | `GET /dictionary` |
| Повторение | Добавить слово вручную | Локальная заглушка | `POST /repetition-list/words` |
| Упражнение | Получить слова задания | Локальная заглушка | `POST /exercise-sessions` |
| Упражнение | Сохранить результат задания | Только `console.log` | `POST /exercise-sessions/{id}/complete` |

Настройка `dictionaryWordsPerPage` пока локальная. Для первой версии отдельный
бэкенд-вызов для неё не обязателен.

## 4. Общие модели

### User

Текущий TypeScript-тип:

```ts
type UserInfo = {
  id: string
  name: string
  phone: string
  avatar: string
  email: string
  createdAt: string
}
```

Рекомендуемый JSON:

```json
{
  "id": "user-id",
  "name": "Иван",
  "phone": "+79991234567",
  "avatar": "https://api.example.org/media/avatars/user-id.webp",
  "email": "user@example.org",
  "createdAt": "2026-07-28T10:20:30.000Z"
}
```

`avatar` может быть пустой строкой, если изображение не задано. `email`
сейчас отображению и редактированию не подлежит, но присутствует в модели.

### DictionaryWord

```ts
type DictionaryWord = {
  id: number
  english: string
  russian: string
  repeatCount: number
  successfulRepeatCount: number
  failedRepeatCount: number
}
```

Инвариант:

```text
repeatCount = successfulRepeatCount + failedRepeatCount
```

Счётчики должны быть пользовательскими, а не общими для всех пользователей.

Рекомендуется сразу вернуть признак ручного выбора, чтобы состояние зелёной
кнопки восстанавливалось после перезагрузки:

```json
{
  "id": 42,
  "english": "brother",
  "russian": "брат",
  "repeatCount": 3,
  "successfulRepeatCount": 2,
  "failedRepeatCount": 1,
  "isSelectedForRepetition": true
}
```

### Результат упражнения

Текущие типы:

```ts
type Lang = "en" | "ru"

type WordStat = {
  id: number
  retries: number
  isOk: boolean
  variants: string[]
  skipTimes: number
  hintTimes: number
  errorTimes: number
}

type Task = {
  lang: Lang
  list: {
    id: number
    word: string
    translate: string
  }[]
  results: WordStat[]
}
```

Семантика направления:

- `lang: "en"`: показано русское слово, пользователь вводит английское;
- `lang: "ru"`: показано английское слово, пользователь вводит русское.

`variants` содержит введённые пользователем варианты ответа. Эти значения
могут содержать пользовательские данные, поэтому не должны попадать в
нефильтрованные системные логи.

## 5. Авторизация

### POST `/api/v1/auth/login`

Запрос:

```json
{
  "phone": "+79991234567",
  "pinCode": "1234"
}
```

Валидация, уже заданная фронтендом:

- российский телефон: 10 цифр без `+7` во внутренней форме UI;
- в API рекомендуется передавать полный номер `+7XXXXXXXXXX`;
- PIN содержит ровно 4 цифры.

Рекомендуемый ответ `200`:

```json
{
  "user": {
    "id": "user-id",
    "name": "Иван",
    "phone": "+79991234567",
    "avatar": "",
    "email": "user@example.org",
    "createdAt": "2026-07-28T10:20:30.000Z"
  },
  "accessToken": "access-token",
  "refreshToken": "refresh-token",
  "expiresIn": 900
}
```

Если будет выбрана cookie-сессия, токены из тела ответа не нужны. Это нужно
согласовать до реализации API-клиента.

### POST `/api/v1/auth/register`

Текущая форма передаёт:

```json
{
  "name": "Иван",
  "phone": "+79991234567",
  "pinCode": "1234",
  "avatar": "optional data:image/... base64"
}
```

Правила фронтенда:

- имя после `trim()` — минимум 2 символа;
- телефон — российский номер;
- PIN — ровно 4 цифры;
- аватар необязателен;
- файл аватара — изображение не более 2 МБ.

Для production предпочтителен `multipart/form-data` с бинарным файлом вместо
base64. Возможны два варианта:

1. регистрация без аватара, затем `PUT /users/me/avatar`;
2. единый multipart-запрос регистрации.

Ответ `201` совпадает с ответом входа и сразу создаёт авторизованную сессию.

Конфликт телефона: `409 PHONE_ALREADY_REGISTERED`.

### POST `/api/v1/auth/logout`

Тело не требуется. Ответ: `204 No Content`.

Если используются refresh-токены, сервер должен отозвать текущую сессию.

### GET `/api/v1/users/me`

Нужен для восстановления авторизации после перезагрузки приложения.

Ответ `200`:

```json
{
  "user": {
    "id": "user-id",
    "name": "Иван",
    "phone": "+79991234567",
    "avatar": "",
    "email": "user@example.org",
    "createdAt": "2026-07-28T10:20:30.000Z"
  }
}
```

## 6. Профиль

### PATCH `/api/v1/users/me`

Пока редактируется только имя.

Запрос:

```json
{
  "name": "Новое имя"
}
```

Ответ `200`:

```json
{
  "user": {}
}
```

Поле `user` должно содержать полную актуальную модель пользователя.

### PUT `/api/v1/users/me/avatar`

Рекомендуемый формат: `multipart/form-data`, поле `avatar`.

Ограничения:

- только изображения;
- максимум 2 МБ до серверной обработки;
- сервер должен проверять реальный MIME-тип, а не только расширение;
- желательно нормализовать размер и формат изображения.

Ответ `200`:

```json
{
  "avatar": "https://api.example.org/media/avatars/user-id.webp"
}
```

### PUT `/api/v1/users/me/pin`

Текущая форма собирает только новый PIN и его подтверждение. Подтверждение
нужно проверять на клиенте и не обязательно отправлять серверу.

Минимальный запрос:

```json
{
  "newPinCode": "5678"
}
```

Предпочтительный безопасный вариант:

```json
{
  "currentPinCode": "1234",
  "newPinCode": "5678"
}
```

Сейчас UI не запрашивает `currentPinCode`; это открытый вопрос.

Ответ: `204 No Content`.

## 7. Словарь

### GET `/api/v1/dictionary`

Параметры:

| Параметр | Тип | Значение |
| --- | --- | --- |
| `search` | string | Подстрока русского или английского текста |
| `sortBy` | string | `russian`, `english` или `repeatCount` |
| `sortOrder` | string | `asc` или `desc` |
| `limit` | number | Сейчас одно из `10`, `20`, `30`, `50`, `100` |
| `offset` | number | Сейчас `0`; нужен для будущей пагинации |

Пример:

```http
GET /api/v1/dictionary?search=дом&sortBy=russian&sortOrder=asc&limit=30&offset=0
```

Ответ `200`:

```json
{
  "items": [
    {
      "id": 4,
      "english": "home",
      "russian": "дом",
      "repeatCount": 6,
      "successfulRepeatCount": 5,
      "failedRepeatCount": 1,
      "isSelectedForRepetition": false
    }
  ],
  "total": 1
}
```

Требования:

- поиск регистронезависимый;
- поиск выполняется одновременно по `english` и `russian`;
- `total` считается после фильтрации, но до `limit/offset`;
- сортировка текста должна корректно работать для русского и английского;
- статистика и ручной выбор относятся к текущему пользователю.

### POST `/api/v1/repetition-list/words`

Добавляет слово или фразу в пользовательский список повторения.

Запрос:

```json
{
  "wordId": 42
}
```

Операция должна быть идемпотентной: повторный запрос не создаёт дубликат.

Ответ `200`:

```json
{
  "wordId": 42,
  "isSelectedForRepetition": true
}
```

Важно: фразы разрешено добавлять вручную. Автоматический выбор фраз не
выполняется, но кнопка «Повторить» для них остаётся доступной.

Удаление из списка в текущем UI отсутствует. Возможный будущий endpoint:

```http
DELETE /api/v1/repetition-list/words/{wordId}
```

## 8. Формирование упражнения

### Бизнес-правила текущего фронтенда

В список упражнения входят:

1. автоматически выбранные словарные записи с минимальным `repeatCount`;
2. записи, вручную добавленные пользователем через кнопку «Повторить».

Для автоматического выбора учитываются только записи без пробелов одновременно
в `english` и `russian`. Если пробел есть хотя бы с одной стороны, запись
считается фразой и автоматически не выбирается.

Ручной выбор имеет приоритет: вручную выбранная фраза включается в упражнение.

Одна и та же запись выполняется в двух направлениях:

- русский → английский;
- английский → русский.

### POST `/api/v1/exercise-sessions`

Предпочтительнее создавать серверную сессию, а не просто получать массив слов:
это даст стабильный состав задания и защитит отправку результатов от дублей.

Запрос:

```json
{
  "code": null
}
```

`code` берётся из необязательного маршрута `/:code?`. Его назначение пока не
определено и требует уточнения.

Ответ `201`:

```json
{
  "sessionId": "exercise-session-id",
  "words": [
    {
      "id": 42,
      "english": "brother",
      "russian": "брат"
    }
  ],
  "createdAt": "2026-07-28T10:20:30.000Z"
}
```

Фронтенд самостоятельно строит оба направления из `english` и `russian`.

Если сервер не нашёл слов для упражнения, допустим ответ `200/201` с пустым
массивом `words`.

### POST `/api/v1/exercise-sessions/{sessionId}/complete`

Запрос соответствует текущему событию `finish`:

```json
{
  "tasks": [
    {
      "lang": "en",
      "results": [
        {
          "id": 42,
          "retries": 1,
          "isOk": true,
          "variants": ["brother"],
          "skipTimes": 0,
          "hintTimes": 0,
          "errorTimes": 0
        }
      ]
    },
    {
      "lang": "ru",
      "results": [
        {
          "id": 42,
          "retries": 1,
          "isOk": true,
          "variants": ["брат"],
          "skipTimes": 0,
          "hintTimes": 0,
          "errorTimes": 0
        }
      ]
    }
  ]
}
```

Поле `list` из клиентского типа `Task` отправлять не рекомендуется: сервер уже
знает состав сессии. Это исключает подмену слов и уменьшает запрос.

Операция завершения должна быть идемпотентной. Повторный запрос для одной
сессии не должен повторно увеличивать статистику.

Ответ `200`:

```json
{
  "sessionId": "exercise-session-id",
  "status": "completed",
  "completedAt": "2026-07-28T10:30:00.000Z",
  "words": [
    {
      "id": 42,
      "repeatCount": 4,
      "successfulRepeatCount": 3,
      "failedRepeatCount": 1
    }
  ]
}
```

## 9. Настройки

Сейчас существует только:

```ts
dictionaryWordsPerPage: number // default: 30
```

Она используется как лимит таблицы и пока может оставаться локальной.

Если нужна синхронизация между устройствами:

```http
GET   /api/v1/users/me/settings
PATCH /api/v1/users/me/settings
```

```json
{
  "dictionaryWordsPerPage": 30
}
```

## 10. Требования безопасности

- PIN нельзя хранить в открытом виде; нужен стойкий password hashing
  (например, Argon2id) и уникальная соль.
- Нельзя логировать PIN, access/refresh-токены и полные тела запросов
  авторизации.
- Нужен rate limit на вход, регистрацию и смену PIN.
- Все production-вызовы — только по HTTPS.
- Для refresh-токенов нужна ротация и возможность отзыва сессии.
- Сервер обязан повторить всю клиентскую валидацию.
- Нельзя подключать frontend напрямую к БД.
- В `src/pages/index.vue` сейчас есть комментарий с параметрами подключения к
  БД. Его нужно удалить; если данные реальные, учётные данные следует сменить.

## 11. Открытые вопросы перед реализацией

1. Bearer-токены или защищённая cookie-сессия?
2. Как обновляется access token и где хранится refresh token?
3. Что означает необязательный `code` в маршруте `/:code?`?
4. Как именно увеличивать `repeatCount`: один раз за всю двунаправленную
   сессию или отдельно за каждое направление?
5. Как классифицировать результат как успешный/неуспешный при подсказках,
   ошибках и повторных попытках?
6. Удаляется ли вручную выбранное слово из списка после успешного упражнения?
7. Нужен ли endpoint удаления слова из списка повторения уже в первой версии?
8. Нужна ли серверная пагинация дальше первой страницы словаря?
9. Нужно ли сохранять `dictionaryWordsPerPage` между устройствами?
10. Как загружается аватар при регистрации: отдельным запросом или multipart?
11. Требовать ли текущий PIN при смене PIN?
12. Нужен ли пользователю реальный `email`, если UI его не запрашивает?
